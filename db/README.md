# Charles — database setup scripts

These are NOT applied automatically. Nothing watches this folder. They exist so
the SQL is kept, reviewable, and re-runnable.

To apply: paste **`CHARLES-SETUP.sql`** (all of these, in order, in one file,
generated by `npm run setup-sql`) into Supabase → SQL Editor → Run, then run
the checks in `docs/SUPABASE-SETUP.md`. Or paste them one at a time, in
order. Every one of them is safe to run more than once.

Charles is built from Charlie, and the tables keep Charlie's names: a `businesses`
row is one household's money, `business_map` is the Money Map, `owner_notes`
is what Charles remembers about the person. `0033` says why. The market-only data
migrations Charlie carried (Kenya, Nigeria, Ghana, Uganda, and its South
African business library) are gone; `0034` is Charles's library.

## Why two of these are load-bearing

**`0001`** is the difference between "our research is public" and "every
person's private money data is public". Before it, RLS was off on every table.

**`0005`** contains `claim_job`, which uses `FOR UPDATE SKIP LOCKED`. That is
what lets two function instances wake at the same moment and never claim the
same job. Without it, a burst of traffic means the same WhatsApp message
handled twice.

## Checking it worked

`docs/SUPABASE-SETUP.md` section 4 is one query that returns every check
with its expected value and PASS or LOOK beside it. The shortest version:

```sql
select relname, relrowsecurity from pg_class
 where relnamespace = 'public'::regnamespace and relkind = 'r' order by relname;
```

Every row must say `true`.
