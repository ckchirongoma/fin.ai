# Charles — set up the database in one paste

Everything the database needs is one file: **`db/CHARLES-SETUP.sql`**. It is
every migration in `db/`, in order, with a banner between them, generated by
`npm run setup-sql`. You paste the whole file once. It is safe to run again
as many times as you like: every statement is `IF NOT EXISTS`, a keyed
upsert, or guarded by a check, and it was applied three times in a row on a
clean Postgres 16 before this was written, with the same result each time.

## 1. Before you paste (two clicks)

1. Supabase → **New project**. Any name; pick the region closest to
   Johannesburg. Wait for it to finish provisioning.
2. **Database → Extensions → search `vector` → enable.** The script also
   tries to enable it, but the SQL Editor's role is not always allowed to,
   and `0010` needs it for the search-by-meaning functions. One click here
   saves one error there.

## 2. Paste

1. Open `db/CHARLES-SETUP.sql` in the repo, select all, copy.
2. Supabase → **SQL Editor → New query** → paste → **Run**.
3. It runs for ten to thirty seconds. The editor shows "Success. No rows
   returned" or the last statement's result; both are fine. If it stops on
   an error, read section 5.

Nothing in the script asks for a key, a number or a secret. Nothing in it is
a person's data. It is schema, policies, the six model rows, the six
WhatsApp templates as drafts, and the South African library.

## 3. Edit yourself: the only lines that are yours to change

Search the script for `INSERT INTO public.model_config`. Those rows are the
starting choice of which model does which job (`router`, `wa_reply`, `help`,
`voice`, `plan_builder`, and `safety` added later in the file). Replace each
`model` value with a slug you have chosen on your OpenRouter dashboard
(OpenRouter → Models → copy the slug). You can do it before pasting, or
afterwards with one `UPDATE` per role in the SQL Editor:

```sql
update public.model_config set model = 'the/slug-you-chose' where role = 'wa_reply';
```

The webhook reads the table on every call, so a change is live at once, with
no redeploy. Nothing else in the file needs editing. The WhatsApp number, the
Meta token, the OpenRouter key and the email address all live in Vercel's
environment variables (`HANDOFF-DEPLOY.md` section 3), never in SQL.

## 4. Did it work? Paste this second query and compare

SQL Editor → New query → paste the whole block → Run. It returns one table of
checks, each with the value it found and the value it should be, and a
`result` column.

```sql
with checks as (
  select 'tables with RLS off' as item, (select count(*) from pg_class where relnamespace='public'::regnamespace and relkind='r' and not relrowsecurity)::text as found, '0' as expected
  union all select 'tables created', (select count(*) from pg_class where relnamespace='public'::regnamespace and relkind='r')::text, '35'
  union all select 'knowledge entries (ZA)', (select count(*) from public.knowledge_entries where country='ZA')::text, '56'
  union all select 'tools (ZA)', (select count(*) from public.tools where country='ZA')::text, '30'
  union all select 'knowledge entries older than 90 days', (select count(*) from public.knowledge_entries where verified_on is null or verified_on < current_date - 90)::text, '0'
  union all select 'tools older than 90 days', (select count(*) from public.tools where verified_on is null or verified_on < current_date - 90)::text, '0'
  union all select 'money areas in the library', (select count(distinct domain) from public.knowledge_entries)::text, '8'
  union all select 'model_config rows', (select count(*) from public.model_config)::text, '6'
  union all select 'model roles', (select string_agg(role, ',' order by role) from public.model_config), 'help,plan_builder,router,safety,voice,wa_reply'
  union all select 'WhatsApp templates (drafts)', (select count(*) from public.wa_templates where meta_name like 'charles_%' and status='draft')::text, '6'
  union all select 'money-journey columns on businesses', (select count(*) from information_schema.columns where table_schema='public' and table_name='businesses' and column_name in ('goal','rule','pending_goal_options','pending_rule_options','kept_questions','map_first','statement'))::text, '7'
  union all select 'old Charlie columns left behind', (select count(*) from information_schema.columns where table_schema='public' and table_name='businesses' and column_name in ('customer','angle','pending_customer_options','pending_angle_options'))::text, '0'
  union all select 'claim_job (the queue) exists', (select count(*) from pg_proc where proname='claim_job')::text, '1'
  union all select 'public-read policies on the library', (select count(*) from pg_policies where schemaname='public' and tablename in ('knowledge_entries','tools') and roles::text like '%anon%')::text, '2'
  union all select 'direct-access policies on person tables', (select count(*) from pg_policies where schemaname='public' and tablename in ('businesses','plans','plan_steps','business_map','decisions','owner_notes','messages','cards','kg_nodes','kg_edges'))::text, '0'
  union all select 'tools the plan library points at', (select count(*) from public.tools where id in ('ncr_complaint','gotyme_goalsave','notes_money_log','sheets_budget','transunion_free_report','experian_free_report','xds_free_report','saps_case','sassa_office','ufiling_uif','sars_efiling','tfsa_account','nhfc_first_home_finance','municipal_indigent_register','nasasa_stokvel','ncr_debt_counsellor','nfo_complaint','cdc_register','safps_protective_registration','fsca_check','bank_fraud_report','sassa_srd_online','debicheck','payshap','gotyme_everyday'))::text, '25'
  union all select 'tools still marked needs_verification', (select count(*) from public.tools where needs_verification)::text, '0'
  union all select 'cards table (the WhatsApp card links)', (select count(*) from pg_class where relnamespace='public'::regnamespace and relkind='r' and relname='cards')::text, '1'
  union all select 'knowledge graph tables', (select count(*) from pg_class where relnamespace='public'::regnamespace and relkind='r' and relname in ('kg_nodes','kg_edges'))::text, '2'
  union all select 'memory card allowed', (select count(*) from pg_constraint where conname='cards_kind_check' and pg_get_constraintdef(oid) like '%memory%')::text, '1'
  union all select 'tracking and queue tables', (select count(*) from pg_class where relnamespace='public'::regnamespace and relkind='r' and relname in ('events','incidents','alert_state','event_daily','owner_notes','knowledge_signals','jobs','safety_events'))::text, '8'
  union all select 'search-by-meaning functions', (select count(*) from pg_proc where proname in ('match_knowledge','match_tools'))::text, '2'
  union all select 'vector extension enabled', (select count(*) from pg_extension where extname='vector')::text, '1'
)
select item, found, expected, case when found = expected then 'PASS' else 'LOOK' end as result from checks;
```

### Success criteria

| Check | Expected | What it proves |
|---|---|---|
| tables with RLS off | 0 | Row-level security is on everywhere. Nobody with the public key can read a person's money. |
| tables created | 35 | Every migration ran. |
| knowledge entries (ZA) | 56 | The whole South African money library landed. |
| tools (ZA) | 30 | All thirty free tools landed, and none of Charlie's business tools came along. |
| knowledge / tools older than 90 days | 0 / 0 | Nothing in the library is already stale. Past 90 days Charles hedges a figure automatically, so this number rising over time is normal; 0 today is the bar. |
| money areas in the library | 8 | income, spending, debt, cushion, credit_record, protection, family_money, goals. |
| model_config rows / roles | 6 / the six names | Every job has a model row. Code never hardcodes a model. |
| WhatsApp templates (drafts) | 6 | The six nudges exist as drafts. They go to Meta for approval from `docs/META-TEMPLATES.md`; the status column tracks that by hand. |
| money-journey columns | 7 | The renames in `0033` happened (goal, rule, and their option columns), and `0036` added the statement column. |
| old Charlie columns left behind | 0 | No duplicate column for the same fact, however many times the script ran. |
| claim_job exists | 1 | The job queue can hand one message to one worker and never two. |
| public-read policies on the library | 2 | The two reference tables are readable by the website without a key. |
| direct-access policies on person tables | 0 | Person data has no anon or authenticated policy at all. Only the backend's service role reaches it. |
| tools the plan library points at | 25 | Every tool a plan step can name exists, so no step points at nothing. |
| tools still marked needs_verification | 0 | Every walkthrough was checked against the live site. |
| knowledge graph tables | 2 | Charles has somewhere to remember what each household's money touches, with where each fact came from. |
| memory card allowed | 1 | The "what Charles knows" card can be made. |
| cards table | 1 | The small pages Charles links on WhatsApp have somewhere to keep their snapshots. |
| tracking and queue tables | 8 | The operator's console, incidents and alerts have somewhere to write. |
| search-by-meaning functions | 2 | The pgvector second pass is in place (empty until embeddings are populated, which is deliberate). |
| vector extension enabled | 1 | Step 1.2 was done. If this is the only LOOK, enable the extension and run the script again. |

Every row `PASS` means the database is done. The next thing is section 2 of
`HANDOFF-DEPLOY.md` (Vercel), then the Meta test number.

## 5. If the script stops on an error

- **`type "vector" does not exist`** or anything mentioning `vector`: the
  extension is not enabled. Database → Extensions → enable `vector`, then run
  the whole script again. Everything before that point is already in place
  and will be skipped.
- **`permission denied to create extension`**: same fix, from the Extensions
  page rather than SQL.
- **Anything else**: copy the error and the banner line just above where it
  stopped (`-- 00NN_name.sql`) and send both. The script is a plain
  concatenation of `db/`, so the file name says exactly which migration it was.

## 6. Keeping the script current

`db/CHARLES-SETUP.sql` is generated. Never hand-edit it. When a migration in
`db/` changes, or `seed/` changes (`node scripts/seed-to-sql.mjs > db/0034_charles_za_library.sql`
first), run:

```bash
npm run setup-sql
```

and commit the result. `test/setup-sql.test.ts` fails if the generated file
is older than the files it is built from.
